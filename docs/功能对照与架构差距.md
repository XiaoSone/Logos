## 已记录的实现决策

1. **先交付游客读经，再接开发账号同步**。游客未连接账号前只写本机；明确同意合并后，个人数据归入账号独立库并同步。开发账号闭环不等于正式短信与生产会话治理完成。
2. **数据索引使用一次导入产生的 JSON 与密文包**。服务端将同一快照导入 PG；不可变书卷/章节结构在内存查，搜索在 PG 查。后续可替换为专用 Repository，不改变 GraphQL 合约。
3. **LocalStore 使用 Drift 自定义 SQL 表**。2026-10-19 升级为 v2：收藏、笔记、进度使用独立字段表；经文关联与标签存 JSON 数组，个人记录保留快照；`sync_queue` 持久化 UPSERT/DELETE、UUID 版本及载荷，按版本确认成功项。旧 `user_data` 在事务迁移成功后删除。详见《游客数据导入协议》。
4. **device.bin 当前放在私有 SQLite settings 中**，内容仍为完整认证密文；设备密钥放 flutter_secure_storage。后续可迁到独立私有文件，降低 DB 写入和 Web 备份负担。
5. **合节保留明确来源**。原文 31,021 个文本单元；展开到 31,092 个节地址。合节子记录共用源文并带 bridgeStart/verseLabel，阅读 UI 仅在起始节展示一次。没有自动臆造某节的拆分文本。
6. **段落增加未标题段、二级小标题和发言人段**。源 s1 为 2,596 个，另有 7 个 s2，最终 2,792 个结构段，避免章首无标题经文丢失。116 个诗篇描述题注（d）和 33 个发言人标识（sp）归入段标题，不并入节正文；数据断言覆盖诗篇 46:1。
7. **Web 为辅助预览**。Android 是主要交付目标，Web 安全存储和浏览器数据生命周期不等于 Android Keystore。
8. **按服务地址与账号隔离**。账号库命名同时含服务地址哈希和 userId；退出保留账号待上传队列、清空游客业务表，保留共享设备经文缓存和显示设置。游客转移有持久化归属与幂等提交标记；细节见《游客数据导入协议》。

1. 在 ARM 真机补齐原 App 运行采样和 Logos 真机排版/性能；用原始截图形成更精确的差异清单。

3. PNVS、邀请码事务、Redis 限流、refreshToken/设备撤销、日志脱敏、隐私导出/注销。
4. 365 条每日经文种子、预热；生产 TLS 固定、私有 APK 签名、PG16/Redis 集成验收。
5. Phase 1.5 个人阅读计划、日历、TTS、图片分享卡片。
6. 达到原方案 Phase 1 验收门槛后，再做 RAG/知识图谱。不要把当前版本标记为原方案所有验收项已完成。
