## 1. 准备环境与保存基线

- [ ] 在旧版 App 中记录现有笔记、收藏、分享记录数量，记录一条笔记的正文和经文引用、最近阅读位置、字体与主题。
- [ ] 在设置的“本地数据”或“个人数据备份”入口导出 JSON，另存到自己的文件中，作为内容备份及核对依据。该导出不等于已经提供一键恢复功能。
- [ ] 保留原 App 数据，采用覆盖安装；不要先卸载、清除应用数据或覆盖手机数据库，否则无法验收旧数据迁移。
- [ ] 准备两个专用开发测试账号 A、B，并决定现有游客数据应该归入哪个账号。勾选合并并连接后，游客个人数据会归入该账号并上传；退出后原游客列表为空是预期行为。

电脑 PowerShell 在项目目录执行：

```powershell
cd D:\Project\pre\Logos
.tools/android-sdk/platform-tools/adb.exe devices
```

从设备列表选择一个当前在线的设备标识。若同一手机出现 IP 与无线发现两条记录，选其中一条即可。将下面的 `手机设备标识` 替换成实际值：

```powershell
.tools/android-sdk/platform-tools/adb.exe -s 手机设备标识 install -r dist/logos-0.1.0-debug.apk
.tools/android-sdk/platform-tools/adb.exe -s 手机设备标识 reverse tcp:8080 tcp:8080
```

本清单编写时，本项目 8080 后端可访问。若后端未启动，在另一个 PowerShell 窗口运行以下命令并保持窗口运行；已有服务时不要重复启动：

```powershell
cd D:\Project\pre\Logos
powershell -ExecutionPolicy Bypass -File tools/dev.ps1 backend
```

手机 App“设置 → 经文服务连接”填写 `http://127.0.0.1:8080/graphql`。无线 ADB 断开后需要重新连接，并再次执行 reverse。

开发登录入口：“我的 → 登录信息 → 账号与同步”。使用两个不同、符合手机号格式的专用测试号码，例如 A：`19900000001`、B：`19900000002`；如这些号码已用于测试，则沿用已知数据或换用未使用的测试号码。开发验证码为 `246810`，开发邀请码为 `LOGOS-LOCAL`。当前不会发送真实短信。

## 2. 按顺序执行

### M01：覆盖升级与旧数据迁移

- [ ] 覆盖安装后先不登录，对照安装前的基线。
- [ ] 打开原有笔记、收藏和分享记录，检查正文、经文引用和数量。
- [ ] 打开阅读页，检查最近位置、字体、主题，以及已有离线经文是否可用。
- [ ] 关闭并重新打开 App，再检查一次。

预期：原数据没有丢失、重复或串位；重启后仍一致。如果手机此前已经升级到数据库 v2，这一步只能验证数据保留，不能算作 v1 → v2 迁移验收；需另用保留旧数据库的设备验证迁移。

### M02：游客操作与登录前校验

- [ ] 新建笔记“验收-G-1020”，选择容易核对的经文，例如约翰福音 3:16–17，保存一段独特正文。
- [ ] 新增一个临时收藏，打开另一章阅读，退出 App 后重开，核对这些操作已保存。
- [ ] 进入“账号与同步”，不勾选同意尝试连接；再使用错误验证码尝试连接。

预期：游客数据在本机持久保存；未同意或验证码错误时不能完成连接，原游客数据不消失。分享记录可以用原有记录核对；如需新建，请手动选择自己的保存目标，不必向他人发送。

### M03：连接 A 并合并

- [ ] 填写账号 A、正确验证码与邀请码，阅读并勾选合并同意，点击“连接开发账号并合并”。
- [ ] 等待同步结束，检查“待上传 0 项”和上次同步时间，确认没有同步错误。
- [ ] 核对游客笔记、收藏、进度和分享记录，尤其检查测试笔记正文及多节经文引用。
- [ ] 重复点击“立即同步”，关闭并重开 App，再核对一次。

预期：显示账号 A；原游客数据归入 A，内容完整且只出现一次；重开后仍是 A。待上传数是合并后的同步任务数，不要求等于点击次数。

### M04：从第二个客户端证明云端恢复

- [ ] 在第二台手机或全新模拟器安装同一新版 APK，连接同一个电脑后端。
- [ ] 真机按准备步骤配置转发；Android 模拟器服务地址使用 `http://10.0.2.2:8080/graphql`。
- [ ] 第二客户端没有原账号本地缓存，登录 A 并完成同步。
- [ ] 核对“验收-G-1020”的正文、经文引用以及收藏、进度、分享记录。
- [ ] 第二客户端修改测试笔记；第一客户端点击“立即同步”后核对修改。

预期：干净客户端能够从服务恢复 A 的数据，另一端修改可以通过同步拉取。当前没有持续实时推送，另一端保持静止时请手动同步或切回前台触发。

只有一台手机时，本项记为“待测”。同机退出再登录读取了保留的账号数据库，不能代替此项；不要为了测试而清除主手机的数据。

### M05：断网修改、强停重开与续传

- [ ] 在线时先到“设置 → 离线圣经 → 下载离线经文”，确认显示“已准备好离线阅读”。
- [ ] 在 A 下创建一个可供删除的临时笔记/收藏，先同步成功。
- [ ] 真正切断后端连接：无线 ADB 场景关闭手机 Wi-Fi；如接有 USB，测试时也拔掉，避免飞行模式下仍通过 USB 转发访问后端。
- [ ] 离线修改测试笔记为“离线版本1”，新建“验收-A-offline”，删除前面准备的临时笔记/收藏；检查待上传数大于 0。
- [ ] 断网阅读已下载经文、搜索、打开笔记。
- [ ] 到 Android 应用信息“强行停止”App 后，保持离线重新打开。不要点击“清除数据”。
- [ ] 恢复网络和 ADB 转发，点击“立即同步”，等待结束。
- [ ] 第二客户端以 A 登录并手动同步，核对新增、修改、删除结果。

预期：离线时数据和 A 的归属保留，出现网络错误允许接受；重开后离线修改仍在。恢复连接后待上传归零，错误解除；另一端看到新内容，删除的记录不会重新出现。失败后的自动重试间隔约 30 秒，也可手动触发。

### M06：账号隔离与未上传数据归属

- [ ] A 断网后新增笔记“只属于A”，确认仍有待上传任务，然后退出当前账号。
- [ ] 检查游客页：不应显示 A 的笔记、收藏、分享、搜索及最近阅读位置；设备经文包和显示设置保留。
- [ ] 恢复连接，用 B 登录。检查 B 不显示 A 的数据；新账号首次使用时应无历史个人数据。
- [ ] B 新增“只属于B”并同步，然后退出 B、重新连接 A。
- [ ] 检查 A 找回“只属于A”，完成续传；不应看到“只属于B”。

预期：两账号及游客之间没有个人数据串用。A 退出后的空游客界面不表示 A 数据删除；重新连接 A 可找回本机缓存及待上传任务。

### M07：同步重试与边界

- [ ] 连续手动同步数次、切后台再回前台、强停重开后同步，核对同一测试笔记/分享记录没有重复。
- [ ] 已登录时尝试修改经文服务地址，确认被阻止；切换账号需先退出当前账号。
- [ ] 可选长时测试：保持同一开发登录超过 1 小时，再编辑并同步，观察失效提示，随后用同一账号重新连接。

预期：重复同步不制造重复数据；登录期间不能改变服务归属；开发令牌失效后仍保留本地内容和待上传任务，重新连接原账号后续传。请自然等待，不要修改手机时间来模拟过期，以免干扰笔记的新旧版本判断。正式短信、刷新令牌与服务端会话撤销不属于本轮已完成能力。
